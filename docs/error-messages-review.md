# 錯誤訊息對照表（定稿草案，待你看過）

**訊息設計原則**

1. **標題俐落**：名詞片語，不超過 8 個字。
2. **內容精簡**：維持 1～2 行（第一行說明狀況，第二行說明因應方式）。
3. **安全提示**：「未變更任何檔案」僅在涉及寫入風險的中止情境出現，不作多餘安撫。
4. **互動確認**：可被覆蓋的操作優先讓使用者確認。**exe（GUI）用對話框按鈕，CLI 用 `[y/N]`；CLI 在非終端機環境（排程、管線）不提問，改報錯並提示 `--replace`。**
5. **用詞**：一律稱「**沙盒**」（對應 `sandbox` 資料夾），「翻譯檔」指 `translations.<語言>.json`。

標 ⟨改⟩ 的是我在你的版本上改過的地方，標 ⟨待⟩ 的是還沒定案。
